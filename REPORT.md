# Звіт до лабораторної роботи №4

## 1. Тема, номер і варіант

- **Тема:** Потокова обробка даних у Java-проєкті
- **Номер роботи:** 4
- **Варіант:** 17 — Спортивна ліга
- **Мова:** Java 21
- **Система збірки:** Maven
- **Версія проєкту:** 4.0.0

## 2. Мета роботи

Мета роботи — виконати рефакторинг обробки даних спортивної ліги з
використанням Stream API та `Optional`. У роботі реалізовано фільтрацію,
перетворення, групування, статистичні операції, сортування з обмеженням
кількості результатів і пошук із безпечним представленням відсутнього
результату.

## 3. Предметна область і формат даних

Предметна область варіанта 17 — спортивна ліга. Об'єкт `Match` містить
господарів, гостей, дату, рахунок, номер туру, відвідуваність і категорію
матчу.

Для лабораторної роботи №4 використовується формат CSV:

```text
home;away;date;homeScore;awayScore;round;attendance;kind
```

Приклад:

```text
Динамо;Шахтар;2026-03-10;2;0;1;12500;LEAGUE
```

Старі п'яти- і шести-польові записи залишаються сумісними. Некоректні
дати, числа, назви команд або кількість полів призводять до повідомлення
про помилку під час обробки.

## 4. Реалізація потокових запитів

Усі запити винесено до класу `MatchStreamQueries`. Методи приймають
`List<Match>` і повертають нові результати, не змінюючи вхідний список.

### 4.1. Фільтрація за туром

Метод `byRound` використовує `filter` і повертає матчі заданого туру:

```java
matches.stream()
        .filter(match -> match.round() == round)
        .toList();
```

### 4.2. Перетворення рахунку

Метод `scoreTexts` використовує `map` і перетворює кожен рахунок на
рядок формату `господарі:гості`, наприклад `2:0`.

### 4.3. Групування за туром

Метод `countByRound` використовує `Collectors.groupingBy` разом із
`Collectors.counting()` і повертає карту виду `номер туру -> кількість
матчів`.

Для контрольного набору:

```text
{1=2, 2=2, 3=1, 4=1}
```

### 4.4. Статистика голів господарів

Метод `homeGoalsStatistics` використовує `mapToInt` і
`summaryStatistics`. У реалізації повертається `IntSummaryStatistics`,
яка містить кількість, суму, мінімум, максимум і середнє значення голів
господарів.

Для шести контрольних матчів сума голів господарів дорівнює `12`.
Для порожнього списку кількість елементів дорівнює `0`.

### 4.5. Top-N матчів

Метод `topByGoalDifference` сортує матчі за різницею рахунку у спадному
порядку. Якщо різниця однакова, другим критерієм є дата за зростанням:

```java
Comparator.comparingInt(Match::goalDifference)
        .reversed()
        .thenComparing(Match::matchDate)
```

Після сортування застосовується `limit`. Від'ємний ліміт відхиляється
через `IllegalArgumentException`, а нульовий повертає порожній список.

### 4.6. Пошук через Optional

Метод `findByTeams` шукає перший матч за парою господарів і гостей та
повертає `Optional<Match>`. Якщо матч не знайдено, повертається
`Optional.empty()`, а не `null`.

## 11. Висновки

У лабораторній роботі реалізовано потокову обробку матчів спортивної
ліги для варіанта 17. Циклічну логіку замінено на декларативні операції
Stream API: `filter`, `map`, `groupingBy`, `summaryStatistics`,
`sorted`, `limit` і `findFirst`. Для пошуку використано `Optional`, що
явно представляє відсутній результат. Додані тести підтверджують
коректність запитів, граничних випадків і незмінність вхідних даних.

## 12. Відповіді на контрольні питання

1. **Чим потік відрізняється від колекції?**
   Колекція зберігає елементи, а потік описує послідовність операцій для їх
   обробки. Потік не є контейнером і не змінює джерело даних.

2. **Які частини має типовий конвеєр Stream API?**
   Джерело, проміжні операції та кінцеву операцію. Наприклад, колекція є
   джерелом, `filter` і `map` — проміжними операціями, а `collect` —
   кінцевою операцією.

3. **Чому проміжні операції називають лінивими?**
   Вони лише описують майбутню обробку і виконуються тільки після запуску
   кінцевої операції.

4. **Що робить `filter` і який тип має його предикат?**
   `filter` залишає елементи, для яких умова повертає `true`. Предикат має
   тип `Predicate<T>`.

5. **Чим `map` відрізняється від `mapToDouble`?**
   `map` перетворює елемент на значення довільного типу, а `mapToDouble`
   створює числовий `DoubleStream` із примітивних `double`.

6. **Для чого застосовується `distinct` і від чого залежить його результат?**
   `distinct` залишає унікальні елементи. Результат залежить від коректної
   реалізації `equals` і `hashCode`.

7. **Чому порядок `sorted().limit(N)` відрізняється від `limit(N).sorted()`?**
   Перший варіант сортує всю колекцію і вибирає найкращі `N` елементів.
   Другий спочатку бере перші `N` вхідних елементів, тому може дати інший
   результат.

8. **Яку роль виконує кінцева операція?**
   Вона запускає лінивий конвеєр і формує результат або виконує побічну дію.

9. **Коли застосовується `Collectors.joining`?**
   Для об'єднання текстових елементів потоку в один рядок із роздільником,
   префіксом або суфіксом.

10. **Як `groupingBy` будує карту груп?**
    Він обчислює ключ групи для кожного елемента і додає елемент до
    відповідного значення карти. Без downstream collector значенням є список.

11. **Як отримати суму в кожній групі через downstream collector?**
    Використати `Collectors.summingInt`, наприклад:
    `groupingBy(Match::round, summingInt(Match::homeScore))`.

12. **Які показники містить `DoubleSummaryStatistics`?**
    Кількість, суму, мінімальне та максимальне значення, а також середнє.
    У цій реалізації для цілочисельної кількості голів використовується
    аналогічний `IntSummaryStatistics`.

13. **Які значення має статистика для порожнього потоку?**
    Кількість і сума дорівнюють нулю, середнє — `0.0`, а мінімум і максимум
    мають спеціальні нескінченні значення. Спочатку потрібно перевірити count.

14. **Як утворюється складений компаратор?**
    Основний ключ задається через `Comparator.comparing` або `comparingInt`,
    а додатковий додається через `thenComparing`.

15. **Чому `reversed()` потрібно застосовувати до окремого ключа до `thenComparing`?**
    Так змінюється напрямок лише основного критерію, а другий критерій
    зберігає потрібний порядок. У top-5 різниця рахунку сортується за спаданням,
    а дата використовується як другий критерій.

16. **Яку проблему розв'язує `Optional` у методі пошуку?**
    Він явно представляє знайдений або відсутній результат і не змушує
    використовувати небезпечний `null`.

17. **Чим відрізняються `orElse`, `orElseThrow` і `ifPresent`?**
    `orElse` повертає запасне значення, `orElseThrow` створює виняток за
    відсутності значення, а `ifPresent` виконує дію лише для наявного значення.

18. **Чому накопичення результату через зовнішній змінний список у `forEach` небажане?**
    Воно створює побічний ефект, ускладнює тестування і може бути небезпечним
    для паралельного виконання. Краще повернути результат через collector.

19. **Які властивості перевіряють під час рефакторингу циклу на потік?**
    Еквівалентність результатів, порядок, порожній вхід, дублікати, межі,
    відсутній результат, відсутність мутації джерела та обробку помилок.

20. **За яких умов паралельний потік може бути виправданим?**
    Для великого обсягу незалежних обчислень, коли витрати на розподіл роботи
    менші за виграш. Для малих колекцій або спільного змінного стану краще
    використовувати звичайний `stream()`.
