# Звіт до лабораторної роботи №2

## 1. Тема, номер і варіант

- **Тема:** Розгортання Java-проєкту та базова обробка даних
- **Номер роботи:** 2
- **Варіант:** 17 — Спортивна ліга
- **Операційна система:** Windows 11
- **Мова програмування:** Java 21
- **Система збірки:** Maven

## 2. Мета роботи

Метою лабораторної роботи є перебудова предметної частини попереднього
проєкту: заміна рядкового запису класом-сутністю з інкапсульованим станом,
валідація під час створення об'єкта та винесення допоміжних показників у
record зі збереженням сумісності зовнішнього звіту і CSV.

У результаті роботи:

- створено незмінну сутність `Match`;
- додано предметну валідацію назв команд, рахунку та відвідуваності;
- створено допоміжний `record ScoreAttendance`;
- збережено формат CSV, статистичні показники та зовнішній звіт;
- розширено модульні тести перевірками сутності.

## 3. Порівняння до і після перебудови

До перебудови `CsvProcessor` самостійно розбирав CSV-рядок, перевіряв
поля та накопичував показники у паралельних локальних змінних. Після
перебудови `Match.fromCsv` є єдиною точкою створення сутності з CSV,
а конструктор `Match` централізовано перевіряє предметні інваріанти.
Стан матчу став незмінним, допоміжні показники представлені
`ScoreAttendance`, а формат вхідного CSV, звіт і значення показників
не змінилися.

## 4. Постановка задачі

Необхідно створити програму для обробки результатів матчів спортивної ліги.

Формат одного запису:

```text
home;away;homeScore;awayScore;attendance
```

де:

- `home` — домашня команда;
- `away` — гостьова команда;
- `homeScore` — рахунок домашньої команди;
- `awayScore` — рахунок гостьової команди;
- `attendance` — кількість глядачів.

Програма повинна:

1. визначати кількість коректних записів;
2. обчислювати середню кількість голів за матч;
3. знаходити найбільшу відвідуваність;
4. обчислювати сумарну відвідуваність;
5. повідомляти про помилки у вхідних даних;
6. не припиняти роботу через один некоректний запис.

## 5. Структура програми

Програма складається з таких основних класів:

- `Main.java` — точка входу в програму та обробка аргументів командного рядка;
- `Match.java` — клас-сутність матчу з `private final` полями,
  конструктором валідації, `fromCsv` і `toString`;
- `ScoreAttendance.java` — допоміжний record показників матчу;
- `CsvProcessor.java` — передавання рядків до `Match.fromCsv` та агрегація;
- `ReportResult.java` — record для зберігання результатів;
- `ReportGenerator.java` — формування текстового звіту;
- `CsvProcessorTest.java` — модульні тести обробки CSV;
- `MatchTest.java` — модульні тести предметної валідації;
- `ReportGeneratorTest.java` — модульні тести генерації звіту.

Потік обробки:

```text
input.csv
   ↓
CsvProcessor
   ↓
ReportResult
   ↓
ReportGenerator
   ↓
console + report.txt
```

## 8. Приклади роботи

Для перевірки програми використовується файл:

```text
data/input.csv
```

Він містить як коректні, так і некоректні записи.

Коректні записи:

```text
Динамо;Шахтар;2;1;12500
Карпати;Зоря;1;1;8500
Полісся;Верес;3;0;10200
Рух;Олександрія;0;2;7300
Львів;Ворскла;2;2;6800
Чорноморець;Колос;1;0;5400
Минай;Дніпро-1;0;3;7200
Оболонь;Кривбас;1;2;6100
```

Некоректні записи:

```text
;Шахтар;2;1;5000
Динамо;Карпати;abc;1;7000
Рух;Верес;-1;2;4500
Полісся;Зоря;2;1
```

Для восьми коректних записів із поточного `data/input.csv` програма отримує:

```text
Коректних записів: 8
Середня кількість голів: 2.63
Найбільша відвідуваність: 12500
Сумарна відвідуваність: 64000
```

У звіті також виводиться інформація про некоректні рядки.

## 9. Тестування

Для тестування використовується JUnit 5.

Запуск:

```powershell
mvnw.cmd -B test
```

Перевіряються такі випадки:

1. коректний CSV-запис;
2. порожній рядок;
3. неправильна кількість полів;
4. неправильний числовий формат;
5. від'ємне значення;
6. порожня назва команди;
7. правильне формування звіту;
8. відсутність коректних записів.
9. створення `Match` через конструктор і `fromCsv`;
10. нульові граничні значення;
11. хибні CSV-значення;
12. стабільне `toString`;
13. значення `ScoreAttendance`.

Повна перевірка проєкту:

```powershell
mvnw.cmd -B clean verify
```

Збірка JAR:

```powershell
mvnw.cmd -B package
```

## 12. Відповіді на контрольні питання

1. **Для чого використовується `pom.xml`?**  
   `pom.xml` описує Maven-проєкт, його залежності, плагіни, версію Java та параметри складання.

2. **Що виконує команда `mvn test`?**  
   Компілює тестовий код і запускає автоматизовані тести.

3. **Що виконує `mvn package`?**  
   Збирає проєкт і створює готовий JAR-файл.

4. **Що таке `main` у Java?**  
   Це точка входу програми, з якої JVM починає виконання.

5. **Для чого використовується `Integer.parseInt()`?**  
   Для перетворення текстового представлення цілого числа у тип `int`.

6. **Що відбувається при передачі `"abc"` у `Integer.parseInt()`?**  
   Виникає `NumberFormatException`.

7. **Навіщо перевіряти кількість полів CSV?**  
   Щоб програма не намагалася звернутися до відсутнього поля та могла повідомити про помилку.

8. **Для чого використовується `split(";", -1)`?**  
   Другий параметр `-1` дозволяє зберігати порожні поля в кінці рядка.

9. **Чому програма не повинна завершуватися через один неправильний запис?**  
   Щоб інші коректні записи продовжували оброблятися, а користувач отримав інформацію про всі знайдені помилки.

10. **Для чого використовується `Path.of()`?**  
    Для створення об'єкта шляху до файла або каталогу з урахуванням особливостей операційної системи.

11. **Чому для роботи з CSV використовується UTF-8?**  
    Щоб українські та інші Unicode-символи коректно читалися на різних системах.

12. **Для чого потрібні JUnit-тести?**  
    Для автоматичної перевірки окремих частин програми.

13. **Які помилки перевіряються у цій роботі?**  
    Порожній рядок, неправильна кількість полів, нечислове значення, від'ємне значення та порожня назва команди.

14. **Що робить `Math.max()`?**  
    Повертає більше з двох переданих числових значень.

15. **Для чого потрібен GitHub Actions?**  
    Для автоматичного запуску перевірок, тестів і складання проєкту після змін у репозиторії.

## 13. Висновки

У лабораторній роботі створено Java-програму для обробки результатів матчів спортивної ліги.

Програма читає дані з CSV-файла, перевіряє їх коректність, обчислює статистичні показники та формує текстовий звіт.

Також створено модульні тести, Maven-конфігурацію та автоматизовану
перевірку через GitHub Actions. Версію проєкту оновлено до `2.0.0`;
після push потрібно створити Git-тег `v2.0.0`. Виконуваний JAR буде
опубліковано як artifact успішного CI-запуску.

Отриманий проєкт може бути зібраний у JAR-файл та запущений з командного рядка.
