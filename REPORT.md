# Звіт до лабораторної роботи №5

## 1. Тема, номер і варіант

- **Тема:** параметризоване сховище, винятки й CSV-експорт у Java-проєкті.
- **Номер роботи:** 5.
- **Варіант:** 17 — спортивна ліга.
- **Клас запису:** `MatchRecord`.
- **Мова:** Java 21.
- **Система збірки:** Maven.
- **Версія:** 5.0.1.
- **Операційна система:** Windows.

## 2. Мета роботи

Мета роботи — доповнити попередній Java-проєкт типобезпечним
параметризованим сховищем, власним винятком із ланцюгом причин,
анотацією CSV-полів, універсальним рефлексивним експортером,
документним CSV-парсером і перевіркою round-trip.

Після виконання роботи застосунок уміє зберігати записи спортивної ліги
у CSV-файлі та відновлювати їх без втрати значень.

## 3. Стан до і після роботи

До лабораторної роботи №5 дані матчів оброблялися поліморфною колекцією
`Match` у пам'яті. Після роботи додано:

- `Repository<T>` для типобезпечного зберігання;
- `DataStorageException` для помилок збереження та імпорту;
- `@CsvColumn` для опису CSV-стовпців;
- універсальний `CsvExporter`;
- `CsvParser`, який підтримує екрановані поля;
- `MatchRecord` для round-trip обміну;
- тести сховища, експорту, імпорту та помилок.

Функціональність лабораторної роботи №4 — класи `Match`,
`LeagueMatch`, `PlayoffMatch`, потокові запити та старий CSV-формат —
збережена без порушення сумісності.

## 4. Параметризоване сховище

Клас `Repository<T>` не використовує raw types і працює з конкретним
типом записів:

- `add(T item)` додає непорожній запис;
- `all()` повертає незмінний знімок усіх записів;
- `find(Predicate<? super T>)` повертає записи, що відповідають умові.

Метод `all()` використовує копіювання списку, тому клієнт не може
змінити внутрішній стан сховища. Метод `find` приймає
`Predicate<? super T>`, що дозволяє використовувати предикати для
супертипів запису.

## 5. Модель даних варіанта 17

Клас `MatchRecord` описує плоский запис спортивного матчу.

| Поле | Тип | Інваріант |
|---|---|---|
| `homeTeam` | `String` | назва не порожня |
| `awayTeam` | `String` | назва не порожня |
| `date` | `LocalDate` | значення не `null` |
| `homeScore` | `int` | невід'ємне |
| `awayScore` | `int` | невід'ємне |
| `round` | `int` | невід'ємний |

Усі поля є `private final`. Методи `equals` і `hashCode` враховують усі
поля запису. Ключ round-trip для варіанта:

```text
homeTeam + awayTeam + date
```

## 6. Анотація `@CsvColumn`

Анотація оголошена з такими параметрами:

- `@Retention(RetentionPolicy.RUNTIME)` — доступна під час виконання;
- `@Target(ElementType.FIELD)` — застосовується до полів.

Поля `MatchRecord` мають такі CSV-назви:

| Поле Java | CSV-стовпець |
|---|---|
| `homeTeam` | `господарі` |
| `awayTeam` | `гості` |
| `date` | `дата` |
| `homeScore` | `рахунок господарів` |
| `awayScore` | `рахунок гостей` |
| `round` | `тур` |

Фактичний заголовок CSV:

```text
рахунок гостей,гості,дата,рахунок господарів,господарі,тур
```

Порядок полів визначається порядком оголошення полів класу та є однаковим
для заголовка і кожного запису.

## 7. Рефлексивний CSV-експортер

`CsvExporter` є універсальним і не залежить від класу `MatchRecord`.
Метод експорту отримує:

```java
CsvExporter.write(path, MatchRecord.class, records);
```

Алгоритм експорту:

1. рефлексією знаходяться поля з `@CsvColumn`;
2. перевіряється доступ до полів;
3. із значень анотацій формується заголовок;
4. значення кожного об'єкта читаються рефлексією;
5. спеціальні CSV-символи екрануються;
6. файл записується через `Files.writeString` у UTF-8;
7. старий вміст файла замінюється через `TRUNCATE_EXISTING`.

Експортер не змінює об'єкти та список сховища.

## 8. Формат CSV та екранування

Один звичайний запис:

```text
Динамо,Шахтар,2026-03-10,2,0,1
```

Приклад екранування коми та подвійних лапок:

```text
"Динамо, ""старе""",Шахтар,2026-03-10,2,0,1
```

Якщо поле містить кому, лапки або перенесення рядка, воно береться в
подвійні лапки. Подвійна лапка всередині поля подвоюється.

Запис і читання виконуються з явним кодуванням:

```java
StandardCharsets.UTF_8
```

## 9. Імпорт і round-trip

`CsvParser` читає весь CSV-документ і підтримує:

- кому всередині лапок;
- подвійні лапки;
- перенесення рядка всередині екранованого поля;
- розділення документа на записи та поля.

Звичайний `split(",")` для цього непридатний, оскільки він помилково
розділяє поле на частини, якщо кома знаходиться всередині лапок.

Метод `MatchRecord.readAll`:

1. читає файл через `Files.readString`;
2. розбирає документ через `CsvParser.parseDocument`;
3. перевіряє заголовок;
4. відновлює записи через `MatchRecord.fromFields`;
5. повертає записи у початковому порядку.

Round-trip перевіряється послідовністю:

```text
об'єкти → CSV → об'єкти → equals
```

Для тестових записів початковий і відновлений списки є рівними.

## 10. Власний виняток і помилки

`DataStorageException` є checked exception і має два конструктори:

```java
DataStorageException(String message)
DataStorageException(String message, Throwable cause)
```

Першопричина не поглинається, а передається через `getCause()`.

| Тип помилки | Приклад | Реакція |
|---|---|---|
| Модель | порожня команда | `IllegalArgumentException` |
| Модель | від'ємний рахунок або тур | `IllegalArgumentException` |
| Формат | кількість полів не дорівнює шести | `DataStorageException` |
| Значення | неправильна дата або число | `DataStorageException` із `cause` |
| CSV | незакриті лапки | `DataStorageException` |
| Файл | відсутній або недоступний файл | `DataStorageException` із `IOException` у `cause` |
| Рефлексія | немає анотованих полів | `DataStorageException` |

Порожній CSV-документ є допустимим і повертає порожній список.
CSV-файл лише із заголовком також не створює жодного об'єкта.

## 16. Відповіді на контрольні питання

1. **Яку проблему розв'язує параметр типу в `Repository<T>`?**
   Він гарантує роботу сховища з визначеним типом записів і прибирає
   небезпечні приведення типів.

2. **Чим параметризований клас відрізняється від raw type?**
   Параметризований клас явно вказує тип, наприклад
   `Repository<MatchRecord>`. Raw type втрачає перевірку типів під час
   компіляції.

3. **Навіщо `Predicate<? super T>` у методі пошуку?**
   Такий запис дозволяє передати предикат для `T` або його супертипу.

4. **Чому `all()` має повертати незмінний знімок?**
   Щоб зовнішній код не міг напряму змінити внутрішній список сховища.

5. **Що таке checked exception і коли він доречний у цій роботі?**
   Це виняток, обробку або оголошення якого компілятор вимагає явно.
   Він доречний для помилок файла, CSV та зберігання, бо клієнт повинен
   явно визначити реакцію на них.

6. **Для чого зберігати `cause` власного винятку?**
   Повідомлення пояснює операцію, а `cause` зберігає технічну першопричину,
   наприклад `IOException`, `DateTimeParseException` або помилку числа.

7. **Чим `Path` і `Files` кращі за складання шляху рядком?**
   Вони є платформонезалежними, типобезпечними та надають готові операції
   читання, запису й створення каталогів.

8. **Чому кодування потрібно задавати і під час запису, і під час читання?**
   Щоб українські назви команд однаково кодувалися та декодувалися на
   різних ОС незалежно від системного кодування.

9. **Що роблять `@Retention(RUNTIME)` і `@Target(FIELD)`?**
   `RUNTIME` залишає анотацію доступною під час виконання, а `FIELD`
   дозволяє застосовувати її саме до полів.

10. **Чому анотація не виконує експорт сама?**
    Анотація є метаданими й лише описує поле. Окремий експортер читає ці
    метадані рефлексією та виконує запис.

11. **Чим `getDeclaredFields()` відрізняється від отримання публічних полів?**
    `getDeclaredFields()` повертає всі поля, оголошені безпосередньо в
    класі, включно з `private` і `final`. Пошук лише публічних полів
    пропустив би приватні поля моделі.

12. **Навіщо перевіряти `trySetAccessible()`?**
    Щоб явно переконатися, що рефлексія має доступ до поля, і повідомити
    `DataStorageException`, якщо доступ заборонено.

13. **Чому порядок полів для CSV потрібно зробити детермінованим?**
    Заголовок і рядки повинні мати стабільний порядок, інакше імпорт може
    зіставити значення з неправильними полями, а результати будуть
    недетермінованими.

14. **Чому `split(",")` не підходить для загального CSV?**
    Він не розуміє лапки й розділяє коми, які є частиною значення поля.

15. **Як екрануються кома, лапка й перенесення рядка в CSV?**
    Поле з комою, лапкою або переносом береться в подвійні лапки, а
    внутрішня подвійна лапка записується двома подвійними лапками.

16. **Чому порожній список потребує окремого параметра `Class<T>`?**
    Без першого об'єкта неможливо визначити тип запису та його поля.
    `Class<T>` дозволяє побудувати заголовок навіть для порожнього списку.

17. **Чим універсальний експортер відрізняється від предметного `fromCsv`?**
    Експортер не знає предметного класу й працює з будь-якими анотованими
    полями. `fromCsv` є предметним методом і знає типи, валідацію та
    правила відновлення конкретного запису.

18. **Які рівні помилок розрізняє програма?**
    Програма розрізняє помилки моделі, формату CSV, значень, файла та
    рефлексії. Помилки моделі є `IllegalArgumentException`, а помилки
    зберігання й імпорту — `DataStorageException`, часто з `cause`.

19. **Що доводить тест round-trip?**
    Що після послідовності «об'єкт — CSV — об'єкт» не втрачаються порядок,
    типи, дати, числа, текстові значення та екрановані символи.

20. **Чому виняток не можна поглинати порожнім `catch`?**
    Порожній `catch` приховує причину помилки та створює хибне враження
    успішного виконання. Помилку потрібно обробити на відповідному рівні
    або передати далі з контекстом і першопричиною.

параметризованим сховищем, власним винятком, runtime-анотаціями та
